# 智慧学工管理系统

这是根据演示系统的可见导航、页面结构与业务关系重建的智慧学工系统。当前使用 PostgreSQL 持久化；仓库自带的数据均为虚构、脱敏数据。

## 本地运行

需要 Node.js `>=22.13.0`：

```bash
npm install
DATABASE_URL=postgresql://... npm run db:migrate
DATABASE_URL=postgresql://... npm run db:seed
npm run dev
```

默认地址为 `http://127.0.0.1:3000`。初始管理员用户名由 `.env.local` 中的 `BOOTSTRAP_ADMIN_USERNAME` 指定，初始密码只保存在该本地环境文件中。

生成覆盖全部 116 个功能入口的虚构测试数据：

```bash
npm run db:seed:test
```

默认生成 500 名学生、6 个测试账号、每个功能 8 条业务记录、流程设计数据和审计日志。数量可通过 `.env.local` 调整；设置 `TEST_DATA_SEED` 可复现同一批数据。该命令会清空旧测试业务数据，但保留管理员账号。

单独重建流程设计数据（流程表单、模型与部署记录）：

```bash
npm run db:seed:flows
```

质量检查：

```bash
npm test
npm run lint
npm audit --omit=dev
```

`npm test` 为双轨道：先跑 `vitest run`（tests/ 下的 .ts/.tsx 单元与组件测试，含 jsdom 渲染），再跑 `node:test`（tests/*.test.mjs，覆盖后端、导入、迁移守卫与渲染产物等）。

使用生产构建在 4173 端口预览：

```bash
npm run build
npm start -- -p 4173
```

## 系统结构

平台包含学工、迎新、宿舍、警务化管理和后台管理五套可切换系统。学生主档是业务中心，学院、专业、班级和辅导员构成组织与数据权限范围。学工系统围绕学生主档分为七个一级域：

- 班级管理：班级与学生组织归属。
- 学生管理：学生主档、缴费记录与缴费凭证。
- 学生事务：请假、销假、学生证补办、节假日去向、返校与投诉。
- 助困管理：勤工助学、困难补助、助学金、学费减免和助学贷款。
- 奖罚管理：奖学金、个人/集体荣誉、违纪、处分、申诉与撤销。
- 团委工作：社团、团籍、第二课堂活动与成绩单。
- 毕业离校：部门离校事项与毕业去向归档。

其他系统：

- 迎新管理：刷卡/人工报到、缴费、报到统计域页（学院/班级/实时分析等 9 项统计合并为页内 Tab）、迎新发布、批次和流程配置。
- 宿舍管理：楼栋、房间、入住、批量排宿、住宿申办域页（入住/调整/退宿/假期宿舍/延缓退宿合并为页内 Tab）、卫生、违纪、考勤、定位规则和报修。
- 警务化管理：学生大队组织、早操与课堂考勤、警容风纪、操行分登记与统计、课程成绩、综合素质考核、体测与训练考勤、执勤安排与应急演练。
- 后台管理：流程设计与待办、政工、校内发布、院系组织、角色与数据/接口权限、用户、菜单、字典和日志。

菜单减负规则：同一业务域的子功能收进域页面的页内 Tab（如奖学金域含评定、种类设置、批次、不可兼得）；「基础配置」「批次发布」阶段入口仅管理员可见，申请、审核、归档阶段按角色展示。

## 通用业务关系

多数评审类业务共享以下主线：

1. 基础配置：维护类型、等级、规则和互斥关系。
2. 批次发布：设置学年、时间窗口、对象范围和院系名额。
3. 学生申请：从学生主档带入组织与住宿信息，填写陈述并上传附件。
4. 分级审核：辅导员、院系和学校按角色处理待办，记录意见与轨迹。
5. 结果归档：生成评定、发放、荣誉、处分或离校结果，并供统计查询。

主要跨域关系：

- 请假申请通过后进入销假/返校环节。
- 奖学金、助学金和困难补助通过互斥规则避免重复获得。
- 违纪事实可生成处分，处分可继续进入申诉与撤销流程。
- 社团活动与第二课堂项目产生积分，汇总到第二课堂成绩单。
- 毕业离校汇总学生、缴费、住宿等事项，全部办结后归档毕业去向。

## 当前实现范围

- 五套顶层系统切换与 116 个功能入口的完整分组导航；同域子功能以页内 Tab 合并，配置/批次阶段仅管理员可见。
- 学生列表筛选、清空、分页，以及可用的批量导入：支持模板下载、CSV/XLSX、拖放上传、逐行校验、错误日志、数据预览和确认入表。
- 学生查看、编辑、新增、照片选择、列表刷新、CSV 导出和可配置显示列均可完成本地交互。
- 与原站一致的独立学生新增页，包含基本信息、学籍信息、个人信息和迎新信息四个分区。
- 每个功能入口可切换，并展示其所在业务阶段、记录列表和处理概览。
- 配置、批次、申请、审核、归档五类完整业务表单，包含附件、名额、审核意见和流程轨迹。
- 通用模块的搜索、清空、导出、刷新、列设置、查看和保存已统一接通；缴费、毕业去向和考勤等“导入”入口使用真实 CSV/XLSX 导入流程。
- 迎新统计图表、宿舍排宿/考勤/报修专用列表，以及后台角色、数据权限、接口权限和日志字段。
- 通用业务关系图、响应式布局和键盘可访问表单。
- PostgreSQL 持久化、JSONB 业务数据、可回滚迁移、管理员初始化和演示数据初始化。
- 使用 scrypt 加盐密码、HttpOnly 会话 Cookie、CSRF 校验、角色权限、登录限流和审计日志。
- 学生查询、新增、编辑、删除、批量导入与刷新持久化；通用业务表单写入按功能隔离的数据记录。
- 流程表单、流程模型和部署记录的数据结构与受保护接口。
- 所有仓库展示数据均为虚构数据；生产数据库连接通过 `DATABASE_URL` 注入。

## 部署现状

系统已实际部署上线，采用 nginx 反向代理 + systemd 服务 + PostgreSQL 的组合：

- `deploy/nginx.conf` / `deploy/nginx-http-bootstrap.conf`：HTTPS 终结与反向代理配置（含 certbot 自动续期定时任务 `deploy/certbot-renew.*`）。
- `deploy/cs1.service`：systemd 服务单元，以 `npm start` 运行生产构建，密钥与数据库连接经 `EnvironmentFile=/etc/cs1.env` 注入，并带沙箱加固项。
- `deploy/setup-postgres.sh` / `deploy/prepare-production-postgres.sh`：生产 PostgreSQL 初始化脚本。
- `scripts/deploy.sh`：服务器端上线流水线（数据库备份→测试→构建→迁移→重启→健康检查），在服务器上以 root 运行。
- `scripts/release.sh`：一键发布脚本，本地执行：推送 GitHub → 服务器 fast-forward 同步 `main` → 部署流水线 → 公网健康检查。

一键发布：

```bash
bash scripts/release.sh                # 要求工作区已提交
bash scripts/release.sh -m "提交信息"   # 有未提交改动时自动 commit
```

服务器（`cs-server`）的 `/opt/cs1` 跟随 GitHub `main` 分支；`.env.local` 与 `/etc/cs1.env` 不受同步影响。本地开发仍以 `npm run dev` 为准；生产链路的域名、HTTPS 与备份均在服务器上由上述配置管理。
